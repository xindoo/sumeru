# 拆书与仿写分析框架

> 核心原则：**拆结构，不拆句子；学方法，不搬名字。**
> 拆书的产物是「可复用的结构模板 + 可验证的写作方法」，不是「换皮文本」。
> 任何进入报告的原文连续片段不得超过 12 字；原作角色名、地名、专有名词不得出现在报告正文中。

## 一、输入与预处理

| 输入形式 | 处理方式 |
|----------|----------|
| 单文件 txt/md | 按「第X章」标题行切分，无标题则整篇作为一章 |
| 章节目录 | 按文件名数字排序，首行作为章节标题 |
| 用户粘贴片段 | 仅做局部拆解，明确标注「样本不足，结论置信度低」 |

先跑机械统计，再写定性结论：

```bash
python3 skills/sumeru-deconstruct/scripts/analyze-book.py --file 参考书.txt
# 或
python3 skills/sumeru-deconstruct/scripts/analyze-book.py --chapters reference/chapters
```

产物：`.sumeru/deconstruct/structure.json`、`拆书数据报告.md`。

## 二、十二个分析维度

### A. 开篇（黄金三章）
1. 第一章前 300 字给了什么：人物 / 困境 / 异常 / 目标 / 悬念，各占多少
2. 金手指/核心变量在第几章出现，出现前用什么维持阅读
3. 前三章各留了什么钩子，钩子类型是否重复
4. 主角初始状态：能力、关系、资源、羞辱点

### B. 人物功能位
5. 主角：欲望 / 阻力 / 代价 / 底线，四件套是否齐全
6. 配角功能位清单：导师、伙伴、对手、红颜、工具人、气氛组，各自出现频率
7. 反派层级：小反派（1-3章）、中反派（10-30章）、大反派（卷末）是否形成阶梯
8. 人物关系变化节点：结盟、背叛、反目、和解分别在第几章

### C. 节奏与爽点
9. 爽点密度：小爽点间隔章数、中爽点间隔、大高潮位置
10. 爽点类型分布：打脸 / 收获 / 身份 / 情感 / 智力 / 探索 / 团战
11. 压抑-爆发比例：每次爆发前铺垫了多少字
12. 章末钩子类型分布（脚本已统计）+ 连续同类钩子的最长连续数

### D. 结构与伏笔
13. 分卷/换地图节点：第几章换场景、换对手、换目标
14. 伏笔埋设-回收距离：短线（<10章）、中线（10-50章）、长线（>50章）
15. 主线推进方式：事件驱动 / 目标驱动 / 关系驱动
16. 信息释放节奏：设定说明是集中倒还是分散给

### E. 语言与视角
17. 对话占比（脚本已统计）：低于 10% 偏叙述，高于 35% 偏对话流
18. 平均段长 / 句长：移动端友好区间为段 50-150 字、句 15-25 字
19. 视角：第一人称 / 第三人称限知 / 全知，是否频繁跳视角
20. 高频重复短语：是作者风格还是注水

## 三、报告结构模板

```markdown
# 《[作品代称]》拆书报告

> 分析对象：仅用于结构研究，报告不含原文段落与原作专有名词。
> 数据来源：X 章 / X 万字。

## 一、一句话结论
这本书靠什么留住读者？（不超过 80 字）

## 二、结构骨架
| 阶段 | 章节范围 | 核心目标 | 主要冲突 | 阶段末变化 |
|------|----------|----------|----------|------------|

## 三、黄金三章拆解
- 第一章：初始状态 → 打破 → 变量 → 小试 → 钩子
- 第二章：验证变量 → 第一次小胜 → 引入对手
- 第三章：第一次真正的代价 → 明确长期目标 → 卷级钩子

## 四、爽点与节奏曲线
（用数据报告里的钩子分布、字数分布做支撑，不要空谈）

## 五、人物功能位
| 功能位 | 出现章节 | 作用 | 退场/转化节点 |
|--------|----------|------|----------------|

## 六、伏笔台账
| 伏笔 | 埋设章 | 回收章 | 跨度 | 回收方式 |
|------|--------|--------|------|----------|

## 七、可复用结构模板（抽象化）
用 [主角] [对手] [变量] [代价] 等占位符描述，不出现任何原作专名。

## 八、仿写方案（差异化）
- 保留：结构比例、钩子密度、功能位配置
- 替换：世界观、人物关系、冲突类型、金手指规则
- 禁止：原作角色名、地名、专有名词、原文句子、标志性桥段组合

## 九、风险与不建议模仿的点
（例如靠擦边、靠注水、靠单一金手指硬撑）
```

## 四、抽象化改写规则

拆书报告里描述情节时，必须做**角色/名词抽象化**：

| 原作写法 | 报告写法 |
|----------|----------|
| 张三在青云宗被退婚 | [主角]在[初始势力]被公开否定 |
| 得到上古神剑 | 获得[核心变量/金手指] |
| 打败王家少主 | 击败[第一层对手]，完成首次立威 |
| 前往中州 | 进入[更高层级地图] |

判断标准：把报告给没看过原作的人看，他能照着写自己的故事，但猜不出原作是哪本。

## 五、数据解读参考值

| 指标 | 偏低 | 健康区间 | 偏高 |
|------|------|----------|------|
| 单章字数（起点） | <2500 | 3000-5000 | >6000 |
| 单章字数（番茄） | <1500 | 2000-3000 | >4000 |
| 对话占比 | <10% | 15%-35% | >45% |
| 平均段长 | <30 字 | 50-150 字 | >300 字 |
| 平均句长 | <10 字 | 15-25 字 | >40 字 |
| 章末悬念占比 | <30% | 50%-80% | 100%（疲劳） |

> 数据只用于发现问题，不用于给作品打分。类型不同，健康区间不同。

## 六、原创性检查（必做）

报告写完后必须跑：

```bash
python3 skills/sumeru-deconstruct/scripts/check-derivative.py \
  --source 参考书.txt \
  --output 拆书报告_某书.md \
  --forbid "原作主角名,原作地名,原作势力名"
```

- 最长连续重合 > 12 字 → 必须改写
- 命中 `--forbid` 专名 → 必须替换为功能位描述
- 复用原作章节标题 → 必须重命名
- 检查结果保存到 `.sumeru/deconstruct/derivative-check.json`

## 七、与下游 Skill 的衔接

- 拆书报告 → `sumeru-outline`：只传「结构模板 + 节奏参数」，不传原作专名与具体情节
- 拆书报告 → `sumeru-topic`：可作为「同类型市场验证」的参考，但不能作为选题创意的唯一来源
- 拆书报告 → `sumeru-write`：只传「钩子类型配比、对话占比、段句长参数」，不传原文

**禁止**：把拆书报告直接当大纲用；把原作角色关系图换名后直接用；把原作章节标题改一个字后复用。
